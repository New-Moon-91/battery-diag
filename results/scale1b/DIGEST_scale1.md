회귀 `tests/test_scale.py`(6건). 결과 원본 `results/scale1b/*.json`, 표 `scale1b_table.csv`.
서버1(workstation, CPU 만 사용) 총 벽시계 약 2시간. 소형 정확해 대조는 컨테이너에서 돌렸다(§5).

## 한 줄 요약

**실규모(λ≈50/일, 16유형, W=1,097)에서는 학습정책이 필요하지 않다.** 유체 LP 상계에 대해
그림자가격 지수 + 유한 대기열 정책(QUEUE_b2)의 갭이 **모든 설비 격자점에서 0.15% 이하**이고,
현행 관행에 가까운 B_fast 조차 용량 ≥ 22대에서 0.6% 이하다. 소형(W=4~6, λ=3.6)에서 보였던
INDEX 13~16%·B_fast 4~5% 의 갭은 **작은 수와 좁은 창고의 효과**다 — 규모가 커지면 사라진다.
따라서 EJOR편의 중심은 «실규모 DCL» 이 아니라 **(i) 상계로 검증한 지수정책 + 설비설계**,
**(ii) 최적화가 중요한 구간(소규모 거점센터)의 식별** 로 옮겨야 한다.

## 1. 방법 — 상계와 정책

### 1.1 유체 LP 상계 (scale.fluid_bound)

배터리 한 대의 여정은 SELL / PU(직행정밀) / FAST→구간 b→{SELL, PRECISE} 중 하나이고,
보유는 시점만 늦추며 여정의 기대보상을 바꾸지 않는다(평균보상, 할인 없음). 어떤 정상정책도
장기적으로는 유형별 도착률 a_k = λ·mix_k 를 여정에 배분하는 것이며, 기간당 정밀 CAP 건이라는
경성 제약은 장기평균 제약을 함의한다. 보관비(≥0)와 창고 제약을 떨어내면

    max Σ_k a_k [ s_k V^S + u_k V^PU + f_k(−C_f+V^S) + Σ_b z_kb (V^PS_kb − V^S) ]
    s.t. s+u+f = 1,  0 ≤ z_kb ≤ f_k(1−pdet_k)p_kb,  Σ_k a_k(u_k + Σ_b z_kb) ≤ CAP

가 g* 의 상계다. CAP 제약의 쌍대가격 μ 가 **정밀용량 한 건의 그림자가격**이다.

**검증.** (a) 강쌍대 — LP 값과 min_μ L(μ) 가 1e-6 상대오차 안에서 일치(모든 셀).
(b) 소형 정확해(w5, 4유형, NARR=4, CAP=1)에 대해 상계 ≥ g*: W=4 +4.95%, W=5 +3.11%,
W=6 +1.98% — 창고가 커질수록 g* 가 상계에 다가간다(상계는 W 와 무관). `tests/test_scale.py`.

### 1.2 정책 (모두 상태열거 없이 act_of(state))

| 정책 | 정의 | 비고 |
|---|---|---|
| B1 | 전량 즉시매각 | 기대값 닫힌식 λΣmix·V^S — 통제변량으로 쓴다 |
| B_fast(thr) | 전량 신속검사, 신호≥thr 상위 CAP 정밀, 나머지 매각 | 정확해 벤치마크와 **같은 정의** |
| INDEX | 근시안 EVSI 지표 | 정확해 벤치마크와 같은 정의. **큰 W 에서 병리적**(§4) |
| LAGR | μ 로 유형별 경로 argmax{V^S, V^PU−μ, v_fast(μ)}, 후보 한계가치순 CAP 건, 미처리 즉시매각 | 대기 없음 |
| QUEUE | LAGR + 미처리 후보 보유: (m−μ) ≥ κ·h·r/CAP | 구조적 과부하에서 안전 |
| **QUEUE_bβ** | LAGR + **유한 버퍼**: 순위 r ≤ β·CAP 이고 m ≥ κ·h·r/CAP 이면 보유 | **본 결과의 주 정책 (β=2)** |

시뮬레이터 `simulate.Simulator`(w7 S1 검증본, 포아송 도착). 기간 T=6,000(+번인 500), 시드 4개.
정책 간 같은 시드 → 같은 도착열. **통제변량 보정 gap_cv**: 시드별 (B1_s − E[B1]) 를 각 정책의 g_s
에서 뺀다(도착열의 풍부/빈약 공통요인 제거). 보정 전후 갭 차이는 0.05~0.2%p 이고 결론을 바꾸지
않는다. 아래 갭은 모두 **gap_cv (상계 대비 %)** 다.

**시뮬레이션 평가의 정합성.** W=4 소형에서 B1·B_fast0·INDEX 의 시뮬레이션 평균이 정확 정책평가
(W4.json)와 |z|<1.5 로 일치한다(T=40,000).

## 6. 결론 — EJOR편 방향에 대한 판정

1. **실규모 DCL 은 하지 않는다.** 상계 대비 0.15% 안에서 작동하는 닫힌 형태 정책이 있고, 그 안에
   피할 수 없는 보관비가 들어 있다. 롤아웃 DCL(w7 S2~S6)은 **중단**한다.
2. **정확해 + 유체 상계 «샌드위치»가 방법론의 뼈대가 된다.** 소형에서는 정확해가 상계가 느슨함을
   보이고(2~5%), 규모가 커지면 상계가 닿는다(0.1%). 정책 품질은 모든 규모에서 **상계 대비 갭**으로
   보고할 수 있다 — SPEC §5.1 이 비워 두었던 «실규모 상계» 가 채워진다.
3. **설비설계는 거의 닫힌 형태다.** 정밀수요 = 도착의 38.9%(가격·유형구성이 정함), M\* = 수요 + 2기간
   버퍼(λ=50 에서 20~22대), W\* ≈ 점유 p99(2~2.5일분). 72점 격자(SPEC §4)를 학습으로 훑을 필요가 없다 —
   시뮬레이션 7초/셀이다.
4. **논문의 질문이 바뀐다.** «어떻게 학습하는가» → **«규모가 선별 문제를 어떻게 바꾸는가».** 작은 센터
   (현행 거점)에서는 최적화와 창고가 중요하고, 큰 허브(2027 민간센터)에서는 단순 지수 + 2일 버퍼로 충분하다.
   이것은 **집중화의 숨은 편익(통계적 풀링)** 이라는 정책 함의를 갖는다 — RCR편의 «창고는 용량을 대체
   못한다»와 짝이 된다.
5. **디코더·표현상한·규모전이(v5c·w6)는 EJOR편에서 빠진다.** 그 자체로 짧은 방법 논문으로 분리.

## 7. 확인 불가 · 남은 것

- λ=5 셀의 1.9% 가 상계의 느슨함인지 정책의 부족인지 — 16유형 정확해가 없어 **분리 불가**. 4유형
  소형(§5)에서는 상계 느슨함이 2~5%, 정책 부족이 0.7~1.7% 였다.
